7. EL PROBLEMA QUE SCREENPLAY INTENTA RESOLVER
============================================================

Cuando una automatizacion crece podemos terminar con muchas:

funciones

acciones

consultas

localizadores

datos

validaciones

Screenplay propone organizar ese comportamiento alrededor
de un Actor y separar responsabilidades.

La pregunta deja de ser solamente:

Que funcion debo ejecutar?

Y comienza a ser:

Quien realiza el comportamiento?

Que quiere conseguir?

Como realiza la accion?

Que necesita conocer?

============================================================
15. ACTOR
============================================================

El Actor representa quien realiza el comportamiento.

Codigo:

const diego = actorCalled('Diego');

En lugar de tener un usuario implicito ahora tenemos
un participante explicito en el escenario.

============================================================
16. TASK
============================================================

La Task representa una intencion.

En nuestro escenario:

CreateTodo

representa:

crear una tarea

La Task debe decir QUE quiere conseguir el Actor.

No debe concentrarse primero en detalles tecnicos.

============================================================
17. INTERACTION
============================================================

La Interaction representa una accion concreta.

En nuestro escenario:

AddTodoItem

es responsable de modificar realmente la lista.

La Interaction responde a:

COMO se realiza la accion?

============================================================
18. QUESTION
============================================================

La Question representa informacion que el Actor
necesita conocer.

En nuestro escenario:

PendingTodoCount

consulta la cantidad de tareas pendientes.

Una Question consulta.

No modifica el sistema.

============================================================
19. ATTEMPTSTO
============================================================

El Actor ejecuta comportamiento utilizando:

attemptsTo()

Codigo:

await diego.attemptsTo(
  CreateTodo('Preparar capacitacion'),
);

Esto permite que el codigo pueda leerse como:

Diego intenta crear una tarea.

============================================================
20. ANSWER
============================================================

El Actor consulta informacion utilizando:

answer()

Codigo:

const pendingCount = await diego.answer(
  PendingTodoCount(),
);

Esto expresa que el Actor obtiene una respuesta
sobre el estado del sistema.

23. COMPARACION DIRECTA
============================================================

BEFORE:

addTodoItem('Preparar capacitacion');

const pendingCount = pendingTodoCount();

------------------------------------------------------------

AFTER:

await diego.attemptsTo(
  CreateTodo('Preparar capacitacion'),
);

const pendingCount = await diego.answer(
  PendingTodoCount(),
);

Ambas soluciones producen el mismo resultado.

La diferencia se encuentra en como se expresa
y organiza el comportamiento.

26. IMPORTANTE - NO TODO ES UNA TASK
============================================================

Task:

Representa una intencion o actividad de negocio.

Ejemplo:

Crear una tarea.

------------------------------------------------------------

Interaction:

Representa una accion concreta.

Ejemplo:

Agregar un elemento a una lista.

Posteriormente podria representar:

hacer click

escribir texto

navegar

------------------------------------------------------------

Question:

Representa una consulta.

Ejemplo:

Cuantas tareas pendientes existen?
